# 本轮改动与验证记录

验证日期：2026-10-05。环境：Windows、Bun 1.4.2，项目原始 ZIP 的解压副本。

## 已实现

- 行为评测将必需工具缺失、禁止工具、无效参数、必需证据缺失、必需证据过期、空回答和工具次数超限计入失败判定。已测 groundedness 低于 0.8 也计为失败。
- CLI 增加默认为 1 的绝对通过率门槛；旧基线与历史实验不改写。
- 摘要、章节和报告列表项连接 Claim Verifier，持久化来源执行 ID 与验证结果。验证上限 12 次、每次 15 秒，计入研究调用预算；恢复时复用已保存结果。
- UI 区分来源支持、矛盾、证据不足和未验证；旧报告不冒充已验证。Markdown 导出保留这些结果。
- 研究置信度明确区别于经校准的投资成功概率。校准权重的实际应用范围未扩大。
- 修复全部被清洗的注入文本又回退到原文的问题；验证模型收到的外部内容标记为数据，传输错误不把原始响应写入报告。
- 增加公开只读的研究验收脚本，覆盖数据采集、综合、验证、持久检查点和 Markdown 输出。新增脚本纳入常规类型检查。
- 修复删除 Pi 会话的测试使用固定 `/tmp/pi` 的跨平台问题；Git SHA 测试允许来源为未包含 Git 历史的 ZIP。
- 文档按当前工作流修正：完整 smoke benchmark 仍为手动执行，PR 覆盖工作区回归测试。

## 验证结果

| 检查 | 结果 |
|---|---|
| `bun test --isolate --timeout 20000` | 1694 pass / 8 skip / 0 fail，185 文件 |
| 工作区 `bun run typecheck` | core、i18n、shared、ui、electron 通过 |
| `bun run typecheck:scripts` | 新验收脚本、评测 CLI 与新增 CLI 回归测试通过 |
| `bun run build` | UI、Electron renderer、preload、main 构建通过 |
| `bun run research:acceptance -- --mode fixture` | 通过；脚本化因果声明被标为证据不足，来源数据声明按 fixture 预期处理 |
| 实际验证组件视觉检查 | 中文、明暗主题、四种状态和旧报告提示均已检查 |

8 项跳过包括未提供的真实账户 fixture 和当前主机不能创建符号链接的安全测试，未把它们计为通过。

smoke 原先在未调用所需工具或未返回证据时也显示通过。修正后正确暴露本地规则 Agent 的限制：11 项缺少必需工具，11 项没有满足要求的证据。这个结果不代表 Pi/LLM 模型的完成率；没有通过改写旧基线或降低默认门槛掩盖失败。

构建保留既有的大 chunk 提示。视觉检查是对真实 React 验证组件的渲染检查，不是完整桌面 E2E。
