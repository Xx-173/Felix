## 已完成的借鉴

参考项目将自选管理作为完整页面，并有市场上下文、分组与列表排序等功能。
Felix 此前将会话和自选放在侧栏底部的限制高度区域，容易出现多层滚动及输入框截断。

- 工作台入口现在打开独立的页内页面，自选与会话分为两个标签，使用整页滚动。
- 自选列表支持代码／名称搜索、按市场筛选、添加顺序／代码排序、添加与移除。
  选择股票后进入现有行情、K 线、财务报表与新闻详情，顶部可返回工作台。
- 列表显示市场和对应货币单位，沿用数据来源、示例标记与更新时间提示。
  市场筛选只是整理现有自选，不会授予行情权限或自动提供新市场的数据。
- 会话列表显示完整标题、更新时间、消息数量和最近涉及的标的，可搜索和继续研究。
  删除前确认；取消或后端拒绝删除时保留原记录。
- 桌面与浏览器共用实现；窄屏下采用图标导航和较宽的列表卡片。
  从会话页打开当前会话也能切换到研究助手。
- 命令面板可以直达工作台和会话页面；其标的快捷操作继续打开行情详情。

## 本次完善：工作台、自选与行情体验

进一步阅读上游 v0.3.5 的自选页面、批量导入组件与行情处理流程，按 Felix 的
TypeScript 架构实现以下交互，两端继续共用组件：

- 自选分组可新建、重命名、删除及筛选；一个标的可以归入多个分组。
  删除分组有确认步骤，保留自选标的；移除标的会同步清理分组成员。
- 粘贴代码或读取 TXT/CSV 后先预览，区分新增、已有、重复、格式错误与容量超限。
  仅接受含市场后缀的明确代码，不推断裸代码所属市场；取消不写入。
  可将新增标的直接加入指定分组，文件限制为 20KB。
- 每个标的显示实际供应商、行情时间及示例／延迟／缓存／刷新失败状态。
  超过 15 分钟的时间仅提示行情时点较早，不据此断言停牌或接口故障。
  获取成功也不会自动标注为实时行情。
- 手动刷新按每批最多 4 个请求执行。刷新失败保留已有真实报价及其时间，
  显示失败原因；没有真实报价时才使用明确标注的内置示例。
- 分组保存在现有 workspace 文档中，支持 SQLite 和 PostgreSQL，沿用账号隔离。
  桌面重启、账号登录及跨浏览器恢复包含分组；旧版仅更新自选的调用不会抹去分组。
  当前上限为 40 个标的、20 个分组，名称最多 40 个字符，服务端与桌面端统一校验。

## 值得继续完善的部分

市场看板、自选表格与可拖动的新会话悬浮入口已进一步借鉴 v0.3.5 的页面组织。
Felix 有 A 股／港股／美股三个标签，保留供应商缺失及权限不足的状态。
尚未接入 TSP 的全市场快照或行业聚合接口，因此全市场广度、成交额和热度仍显示未提供；
已有自选统计使用明确的观察集口径。详细交互和验证见 [界面调整](workbench-design.md)。

| 方向 | Felix 已有基础 | 适合借鉴的下一步 | 优先级 |
| --- | --- | --- | --- |
| 数据质量与来源 | 缓存、供应商路由、每个标的的来源／时间／延迟与失败提示 | 集中展示不同市场、供应商接口及账号行情权限的可用能力 | 高 |
| 自选组织 | 账号隔离、搜索／筛选／排序、分组、批量导入预览与兼容存储 | 在确有需求时增加分组导出和用户定义排序 | 中 |
| 筛选结果可解释性 | `screening/service.ts` 有界候选集、确定性规则、失败记录与结果仓库，已有机会发现页 | 明确显示本次扫描范围、数据覆盖、规则阈值与命中依据；缺少字段时提示不能判断，而不是按零值计算 | 高 |
| 提醒与任务记录 | 已有提醒引擎、市场开闭市门控、触发事件日志、自动化调度和每日简报 | 加强规则运行记录、任务进度、重试和通知送达状态；统一链接回股票详情与研究证据 | 中 |
| 图表研究 | 已有 K 线、周期选择与研究／对比页面 | 把常用指标、参数解释、对比与事件标记放到同一研究路径；确认供应商与计算口径后再扩展指标 | 中 |
| 历史回测 | Felix 的 Agent 评测不是投资策略回测 | 若用户确实需要，再独立设计历史数据、复权、交易日、手续费与滑点；在能复现数据及交易规则前不展示收益结论 | 后续独立项目 |

上述“下一步”均为建议，尚未在本次改动中实现。参考项目的 README 同样描述了市场差异、免费数据限制与尚未接通的部分，因此不能将其所有介绍视为各市场均完整可用。

## 保持 Felix 的部署方式

参考项目的自托管交互可以借鉴，但 Felix 仍使用自己的多用户账户、权限与数据隔离。
自选分组、筛选历史、通知规则和模型密钥都应按 workspace 归属；模型密钥继续由试用者自行填写。
本地 SQLite 与服务器可选 PostgreSQL 的配置继续使用现有数据库实现。
大范围定时扫描要有并发及频率限制，先服务自己的自选集，再考虑全市场数据任务。
